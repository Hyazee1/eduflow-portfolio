# CP-SAT 排课算法

实现：backend/src/eduflow/adapters/cp_sat.py。业务接口是 Scheduler.solve(Snapshot)，领域不依赖 OR-Tools。独立校验器位于 domain/validator.py。

## 输入与候选

Snapshot 包含机构、实际周一日期、统一时段模板、师生与教室的可用集合、课程要求、已审核需求、规则、锁定课次及基础课次。需求携带已同意教师集合、允许时段、排序偏好和可选的指定教室范围。

过滤非已审核需求及不符合年龄年级的学生；教师候选需同时满足资质和已同意审核，教室候选需开放且满足设施。按开课计划、人数、资源容量生成有限数量班次，避免完整的师生教室笛卡尔乘积。

新版候选上限同时考虑全天覆盖，允许充足的答疑需求拆分到五天 S8，常规班覆盖至少 35 个日期时段。每个工作日 S1—S8 的开班数量至少为一；不能用空班或虚构学生补齐。输入一致性诊断指出常规课程仅开放 S8、审核教师/资质缺失、最低人数或设备资源不足。所有已审核需求仍计入满足率分母。

## 联合变量

每个候选班次包含是否开班、时段、教师、教室，以及每条需求是否入班的布尔变量。它们共同表示原需求中的 x[c,t,r,s] 与 y[u,c]，通过分解变量降低组合数量，最终结果仍由 CP-SAT 联合选择。

为教师、教室、学生建立可选时间区间并使用 NoOverlap。成员选择受到共同可用时间、资格、容量、最低人数、指定资源等约束。S8 的课程类型和时长来自时段模板。机构每日至少两节主课、教师每日/周/半天/连续授课上限均加入模型。

局部调整中的无关课次固定；受影响基础班次强制保留其仍有效的成员和班次。只有明确的请假、取消或选课调整能移除相应需求，不能通过丢弃既有成员使方案显得可行。

## 目标优先级

需求满足数始终为首要目标。`balanced` 保留资源均衡目标：偏好排名、教师负载与连续授课、容量浪费、相邻日期课程顺序、学生同日跨教室、基础课次改动、开班数量与下午利用；首要系数大于次要总变化上界。

`preference_first` 分阶段按“需求满足数 → 首选命中 → 任一偏好命中 → 资源质量”优化。每阶段以已经独立校验的较好方案作为提示和不退步下界，后续超时仍保留有效 incumbent。比较结果使用 `(满足数, 首选数, 任一偏好数)`，不再只比较满足总数；因此同为 668 条需求时不会丢失更好的偏好结果。参考版本的源数据、规则与 revision 同步保存，过期参考不能静默生效。

每天第五节授课增加软惩罚，鼓励至少四节空闲，教师轮换与负载均衡继续作为软目标；每日上限五节保证至少三节空闲，相邻两天至少六节。不能为增加轮换而牺牲可满足需求或放宽硬约束。

这些是优化目标，合法 FEASIBLE 方案不保证每项偏好都满足，也不表示全局最优。UI 与报告保留实际状态、耗时、目标、界及未满足原因。

## 大规模分阶段求解

没有基础或锁定课次且需求超过 100 条时，先进行分组的全部需求可行性预求解，预算不超过 12 秒和总预算的 30%。分组受限模型失败并不能证明完整模型无解，因此继续可选需求分组与完整联合模型。

已有可行结果作为完整模型提示，用剩余预算优化。最终按上述优先序比较真实需求 ID 和偏好命中；较低覆盖结果不能替换已验证的较好结果。可行性预求解及保留方案明确标为 FEASIBLE，不伪报全模型 OPTIMAL。

默认总求解预算 60 秒，可配置至 300 秒；模型构造与独立扫描会产生少量额外墙钟耗时。搜索随机种子固定为 42，多线程搜索的耗时和具体方案仍可能变化。

## 状态与发布

| 状态 | 行为 |
|---|---|
| OPTIMAL | 找到并证明当前模型目标最优；仍须独立校验、发布与确认 |
| FEASIBLE | 找到合法方案，未证明最优；可进入校验发布流程 |
| INFEASIBLE | 当前完整模型无解，或确定的必要条件不成立；保存诊断 |
| UNKNOWN | 预算内没有可行方案或证明；不生成可发布版本 |
| MODEL_INVALID | 模型或结果独立校验失败；不生成可发布版本 |

独立校验器重算全部 H 规则和教师负载，不复用模型约束构造代码。人工修改、Agent 建议、发布和最终生效也使用该校验器。缺少确认和资源发生变化时，即使求解结果曾经合法也不能直接生效。

## 真实证据

2026-11-09 独立 220 人回归快照为 53 课次，FEASIBLE，求解器 61.664 秒（测试总耗时约 62.12 秒）；668/668、40/40、独立硬冲突 0。该测试夹具与主库优化任务分开记录，不能混为同一课表。

最终主库周为 68 课次、668/668、40/40、首选 206、任一偏好 336、硬冲突 0。对比保留旧版的首选 106、任一 209，原始 16 类输入表保持一致。300 秒分层预算，任务保存总耗时 308.762 秒，分别记录各阶段与端到端开销；所有阶段 FEASIBLE，没有证明最优。版本已由模拟账号经正常登录与确认 API 完成 736 项必要确认并进入 ACTIVE，不代表真实师生自主确认。具体结果和额外开班的取舍见 [测试报告](testing-report.md)、[分析结论](../analytics/ANALYSIS.md)。

曾出现合法但只满足 365/668 的回归，原记录保留在 solver-220-regression.json；增加完整需求预求解及保留较好结果后，T33 对已知可行数据集断言全部需求满足。数据集不能保证任意新资源配置都可行。

data/feasible.json、conflict.json、resource_shortage.json 提供离线快照。可用 scripts/export_demo_scenarios.py 从固定种子生成，不修改应用数据库。
