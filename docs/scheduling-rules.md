# 排课规则

按实际周一至周五排课。一条需求对应当周一节课，复制下一周需重新审核、求解、发布及确认。

新版启用 H23 全天覆盖：每个工作日 S1—S8 每个时段至少有一班，每周覆盖 40 个时段；允许多位教师并行授课。S1—S7 为常规教学，S8 仅答疑。缺少真实需求、审核、教师或教室时报告不可行，不虚构课次。旧快照缺少此规则字段时按历史规则展示，但不能按新版规则直接发布。

| 时段 | 时间 | 用途 |
|---|---|---|
| S1 | 08:00—08:45 | 常规 |
| S2 | 08:55—09:40 | 常规 |
| S3 | 10:00—10:45 | 常规 |
| S4 | 10:55—11:40 | 常规 |
| S5 | 14:00—14:45 | 常规 |
| S6 | 14:55—15:40 | 常规 |
| S7 | 16:00—16:45 | 常规 |
| S8 | 16:55—17:30 | 仅答疑 |

大课间 09:40—10:00、15:40—16:00；11:40—12:00 缓冲，12:00—14:00 午休，17:30—17:40 收尾。数据库统一配置时段，历史版本保留快照。

教师每天最多五节、每周二十四节，相邻可授课时段最多连续三节，每半天至少空闲一节。S8 按一节计数并额外统计实际 35 分钟，且 S5—S7 至少空闲一节。每工作日至少两节主课。配置只能收紧安全上限。

休息按八个教学时段中未授课的时段统计，每日至少三节，相邻两个工作日合计至少六节。课间和午休单独展示；尽量每天空闲四节及以上、教师轮换和负载均衡属于软目标，需求不足时允许更多空闲。

CP-SAT 联合决定班次、教师、教室、时段和分班。需求须审核通过，教师须有资质并同意开课。资格、年龄年级、共同时间、设施、安全设备、容量和互斥均为硬约束。

大规模首次排课先得到 CP-SAT 可行方案作为完整模型提示，再用剩余预算优化。保留已独立校验方案时返回 FEASIBLE。默认预算 60 秒，模型构造和校验可使总墙钟耗时略高。

需求满足率优先，再考虑偏好、负载、连续授课、资源、多样性、移动、聚合、下午利用及调整数量。偏好不保证全部实现，FEASIBLE 不代表最优。

满足率分母是本周全部已审核需求，输入有问题的需求仍计入并单列原因；待审核数量另列。候选班数同时考虑最低人数、容量和全天覆盖，例如答疑需求足够时至少允许拆为五天的 S8 班次。没有满足全天覆盖的可行方案不能发布，普通调课移走唯一班次同样会被拒绝；紧急安全暂停保留缺口诊断。

独立校验器不复用求解器约束，自动、人工、发布、生效及 Agent 建议均需校验。准确区分五种求解状态，无有效可行解不能发布。

局部调整锁定无关课次，绑定基础 revision；失败或未确认时旧课表继续有效。紧急暂停更新质量报告，主课不足等异常会保留真实冲突。

data 目录有 feasible、conflict、resource_shortage 三套快照，scripts/export_demo_scenarios.py 可重新生成，不修改数据库。
