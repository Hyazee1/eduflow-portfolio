# 使用手册

## 学生

按类别选课程、周和意向时段，在“我的申请”查看审核。“本周课表”区分待确认与正式版本；本人确认后仍需整周必要确认收齐才生效。拒绝须说明原因，系统创建异常工单。

本人请假、调课、调整选课通过异常申请，申请不直接修改旧课表。通知中心查看进度，个人页面维护可用时间并查看反馈。

## 教师

开课审核显示课程、人数、年龄年级、偏好、建议教室类型和必需设备。可同意、拒绝或建议调整，后两项须填写原因。只有同意且具备资质的教师能进入授课候选。已经正式授课的审核不能直接改为拒绝，需使用请假调课流程。

课表显示每日节数、分钟及休息。请假调课选择本人课次，可让 AI 分析工单；批准后由受影响人员确认。课后进入班级名单保存出勤和反馈。

## 管理员

维护 CRM、资质、课程与教室。必需安全设备不能删除，破坏现有课表的修改会被拦截。教室列表的“开放时段”按每周 S1—S8 设置可用时间，已有课次占用的时段需先调整课程。需求池和审核管理页查看教师意见并邀请具备资质的教师。

排课工作台查看异步任务、状态、独立报告和未满足原因；人工编辑后重新校验，仅合法可行版本能发布。逐课次确认，整周统一生效。

局部调整保留旧版本、锁定无关课次；失败、拒绝确认或取消方案时旧课表继续有效。总课表中生效课次的“紧急停课”要求填写原因，立即暂停、释放预订、通知师生并保留异常时间线；后续新安排仍需审批与确认。课表支持课程组、教师和教室筛选。运营、审计、时间线展示真实记录，主要状态及已打开的工单详情每五秒同步，主动操作立即刷新。

## AI 助手

可输入“统计本周课程”“周三下午请假”“分析工单 + 编号”。“周三 S7 调到周四 S5”仅匹配授权课次，多个匹配时要求先明确选择。离线模式使用真实规则和求解器，方案仍需审批确认。


## 从 VS Code 开始试用

1. 打开项目根目录，启动 Docker Desktop 并等待 Engine running。
2. 打开“终端 → 新建终端”，确认位于项目根目录，执行 `.\.venv\Scripts\python.exe .\run.py`，或运行“EduFlow 一键启动”任务。更新源码后执行 `.\.venv\Scripts\python.exe .\run.py --rebuild`。正常启动不需要重新安装依赖、运行 npm 开发服务器或重置数据库。
3. 管理员打开 http://127.0.0.1:8000/login，师生分别在另一浏览器上下文打开 http://127.0.0.1:8100/login。管理账号不能在师生入口登录。
4. 使用 README 的模拟账号；为避免同一入口 Cookie 互相覆盖，教师和学生可用不同浏览器或单独隐私窗口。不同本机端口不能代替独立师生 Cookie 上下文。

## 选课、审核、排课和确认

- 学生：进入“课程选课”，选择周和意向时段，例如周三 S3（10:00—10:45），提交后到“我的申请”查看状态。资料中的年龄、年级和可用时间会参与校验。
- 教师：进入“开课审核”，查看人数、时间、设备与建议教室，选择接受、拒绝或建议调整；拒绝与建议需要意见。只有已接受且有资质的教师进入求解候选。
- 管理员：在需求池和审核管理确认准备情况，到“智能排课工作台”选择周并触发求解。等待任务完成，查看未满足原因和独立校验，硬冲突为零的可行版本才能发布。
- 教师和学生：在待确认课表中逐课次确认。管理员可看确认进度；所有必要确认收齐后，系统在同一事务切换整周有效版本。单人点击确认不会使整周提前生效。
- 调课：从有效课次发起异常，管理员模拟与审批，受影响课次重新确认。无关课次锁定，失败时旧课表保留；紧急停课是单独暂停动作，需原因并留下通知和工单时间线。
- 课后：教师进入班级名单，保存出勤与反馈；学生在个人页面查看本人反馈。S8（16:55—17:30）只用于答疑；普通课程不能通过手工或 Agent 绕过规则。

模拟数据已包含需求和审核，重复演示可能遇到“已申请”或已有待确认版本。先查看当前状态并沿业务操作继续，不要为重演清空演示库。完整自动化演示只重置专用 E2E 测试库。

作品集保存的生效版为 2026-11-09 业务周，随仓库提供分析快照与对账 SQL。新部署使用后台可选的未来演示周重新走业务流程。 [分析工程](../analytics/README.md)

教学时段 S1–S7 用于常规教学，S8 用于答疑。质量报告展示教师负载、休息与未满足原因。

演示账号为管理员 `admin`、教师 `teacher01` 和学生 `student001`。演示密码使用本机配置中的 `DEMO_PASSWORD`。管理员用 8000，师生用 8100，登录时选择对应身份。

要重新演示完整闭环，使用尚未开始的未来演示周，保留当前已生效周。管理员可“复制下一周需求”；学生也可在新周新增符合年龄年级、可用时间的课程申请，教师重新审核。管理员检查准备情况，选择“需求与偏好优先”或“均衡”策略，等待真实求解、独立校验后发布。全天覆盖还需要足够答疑需求、资质和资源，小批需求不一定满足硬约束，失败报告不应通过虚构需求绕过。

新增需求后候选可能过期，不能直接沿用旧结果。发布后，教师和学生在各自待确认课表逐课次确认；只有整周所有必要确认收齐才进入 ACTIVE，单个师生账号确认不会使整周提前生效。旧逾期待确认版本只有管理员明确选定替换对象和最新 revision 后，才可与新发布在同一事务中处理；失败保留旧状态。

淘汰未发布候选时点击“删除草稿”，核对确认框再删除。选课需求、审核和共用资源保留；删除最后一份候选后工作台显示空状态，可以重新排课。发布待确认的版本只能取消发布；曾发布、生效或被替换的版本保留业务历史，不能删除。旧规则候选需重新求解。调课不能移走某时段的唯一班次造成覆盖缺口。

从作品集的 Release 附件下载 `EduFlow_Portfolio.pbix`，用 Power BI Desktop 查看排课优化对比、最终运营总览、需求与偏好匹配、资源配置与全天覆盖、发布确认与质量核验。默认读取内嵌合成快照。课程类型与年级切片器位于需求页，清除筛选可恢复全周值。 [五页 PDF](portfolio/EduFlow-Case-Study.pdf)

## 邀请、改密与会话

管理员“账号与安全”可以邀请新师生、复制一次性链接、重置密码、停用账号和撤销会话。邀请默认 24 小时有效，身份预先绑定；新账号接受后先维护个人可用时间，教师还需管理员配置授课资质。

本人在“账号与安全”修改密码，成功后所有旧会话撤销并重新登录；可查看和撤销自己的会话。停用涉及有效课程的账号时，先按业务调整课程，不能破坏当前资源安排。紧急情况下管理员可先撤销全部会话限制访问。

手机页面提供抽屉导航和按日课表。当前只能在本机通过浏览器设备模拟试用；其他设备不能直接访问本机 127.0.0.1。公网入口保持关闭，后续真实部署须单独授权和规划。
