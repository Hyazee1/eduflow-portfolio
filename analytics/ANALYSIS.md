# EduFlow 排课运营分析与作品集说明

本分析限定于本地测试环境与单周合成数据，比较同一批 220 名学生的 668 条已审核需求。原始需求、偏好、审核、账号和资源共16类源表在改造前后逐表数量及摘要一致。所有结论限定为本机模拟排课与确认，不代表真实学校运营或商业收益。

## 结果与取舍

| 指标 | 优化前保留版本 | 最终 ACTIVE 版本 |
|---|---:|---:|
| 已安排需求 | 668/668 | 668/668 |
| 首选时段命中 | 106（15.87%） | 206（30.84%） |
| 任一偏好命中 | 209（31.29%） | 336（50.30%） |
| 课次数 | 50 | 68 |
| 教学分钟 | 2200 | 3010 |
| 平均班级人数 | 13.36 | 9.82 |
| 教室时间占用率 | 12.57% | 17.20% |
| 教室座位利用率 | 60.07% | 42.49% |

首选命中增加100条、提高14.97个百分点；任一偏好命中增加127条、提高19.01个百分点。满足率继续为100%，没有用修改偏好或删需求来制造提升。

偏好提升伴随额外18个班次和810分钟教学。平均班额与座位利用率下降，说明该方案优先满足时间偏好，不能据此宣称同时节约人力或提高所有资源效率。后续可在需求100%、硬约束0及明确偏好门槛下比较开班数量与利用率，决定是否调整优化策略；不修改当前已生效课表来追求单一展示数字。

最终每天 S1—S8 均有课，40/40 机构时段覆盖；S8 全部为答疑。10间教室都被使用，但400个教室时段的时间占用率为17.20%，因此“全天覆盖”并不等于全校资源满负荷。15/16名教师参与授课，所有教师休息与负载合规；仍有一名教师未排课，不能写成全员授课。

736项必要确认全部同意，包含668项学生确认及68项教师确认；内容指纹一致，804条有效资源预订完整，版本为 ACTIVE。确认是使用模拟账号通过正常登录与业务接口完成，记录保留模拟标识，没有伪装为真实师生的自主确认。

采用300秒分层求解，按满足数量、首选、任一偏好、资源质量依次优化；各阶段均为 FEASIBLE，未证明全局最优。保存的任务耗时包含调度、建模、校验等环节，与阶段 CP-SAT 求解耗时分别记录。单次、单周结果不能说明长期因果、真实用户满意度或公网并发能力。

## 可以展示的分析能力

- SQL：多表关联、CTE、窗口函数识别首选、EXISTS 处理一对多偏好、反向检查必要确认，按固定版本重建四个事实集。
- 数据整理：文本 UUID 与日期数值类型规范、匿名编号、唯一及缺失检查、外键完整性、Power Query 暂存及分类映射合并。
- 共享维度的星型模型支持分类和年级筛选、40 格覆盖矩阵、教师休息矩阵和确认质量核验。五页 Power BI 报表从优化对比进入运营与排课明细。
- 解释与验证：同时报告偏好收益和开班资源代价，用SQL与BI对账；区分人次、人数、确认事项、教学分钟和时间覆盖率。
